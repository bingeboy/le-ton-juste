Section Schematics

Sec 1 — Input & Buffer ↗

V1 signal source → TVS clamp (DTVS1a/b) → C_in coupling cap → R1 shunt → OPA2134 buffer (U1) → R2 isolation → u1_buf node feeding Dwell pot. gen_stage1_input.py ↗

Sec 2 — Dwell Driver may be stale ↗

RV1 Dwell pot (3-terminal divider, 10kΩ lin) → C_drive → BD139 Class-A driver (Q1) biased by R3b/R4 divider. Collector drives L1 primary of REB3S transformer. R5 emitter degeneration, C2 bypass, D3 flyback clamp. gen_stage2_driver.py ↗

Sec 3 — Tank Model & Recovery Amp ↗

L2 secondary (8Ω) → tank input coil model (R/L/C) → 2H output inductance (L_tank_out) → C3 coupling → Rbias → OPA2134 recovery amp (U2), gain set by Ri (470Ω) / Rf (100kΩ) = 213.8× (@1kHz). C4+R6 set HPF corner at ~312Hz. gen_stage4_recovery.py ↗

Sec 4 — Tone & Mix ↗

Tone pot (RV3, 100kΩ audio) after C4 HPF → Rdry (10kΩ) bridges dry path into Mix pot (RV2, 100kΩ audio). C_bright (47pF) across lug 1↔3 for high-frequency compensation. U3 output buffer → R7 → v_out. gen_stage6_full.py ↗

Process

Design Toolchain & Process

This unit was designed and validated before any physical build. Here's the full toolchain — every file linked below is publicly readable in the GitHub repo.

Transparency note Simulation results, test assertions, and documentation were all reviewed by AI (Claude) as part of a multi-round audit process. The audit logs and any known limitations are documented inline in the source files. The repo is public — you can read every gen file, every test, and every simulation directive.
circuit_params.py
Single source of truth for every component value. All generator scripts import from here — changing one resistor value propagates automatically to all netlists and schematics on the next regeneration run.
gen_stage*.py — Netlist generators
Python scripts that write LTSpice-compatible netlists (.net files) programmatically. Each stage has its own generator. Parameters come from circuit_params.py; analysis directives, model bindings, and .meas statements are written inline. The stage 6 full-chain generator (gen_stage6_full.py) covers DC bias, AC frequency response, and transient analysis in three separate netlist variants.
ghost_spring_schematics.py — Schematic generator
Uses the schemdraw library to draw component-level schematics. Part values are pulled directly from circuit_params.py, so the schematic cannot drift from the netlist. Outputs to /tmp/ghost_sec*.png.
validate.py — 386 structural checks
Validates every generated netlist for correct component references, net connectivity, model bindings, and directive syntax before any simulation run. A netlist that fails validate.py is not used.
test_sync.py — 97 simulation assertions (pytest)
Runs against actual LTSpice simulation output. Checks that every .meas result falls within its documented pass band. The MEAS_SPEC dictionary defines the expected directive form for each measurement; the test fails if the netlist diverges from the spec. See test-assertions.md for the full pass-band table and methodology.
LTSpice 26.0.2 — Simulation
Three analysis variants for the full-chain Stage 6 netlist: op (DC bias, 200ms transient with signal killed), ac (gain + HPF corner, powered from ideal ±15V bench rails), tran (100mVpk 1kHz stimulus, peak + stability check).

Known limitation: LTSpice 26 silently ignores FROM= / TO= qualifiers on MAX .meas directives — the measurement runs over the full simulation window regardless. This is confirmed from the simulation log and documented throughout the codebase. The canonical no-op case is the bare MAX abs(V(v_out)) in stage_06_full_tran.net. All tight ceilings for low-drive variants (Dwell=min, Mix=CCW) remain valid because those operating points produce inherently low levels bounded by circuit conditions, not the measurement window. See test-assertions.md for the full analysis.
AI audit (Claude) — Documentation review
Multiple independent audit passes were run on the simulation toolchain, test assertions, and inline documentation using Claude (Anthropic). Audits were treated as adversarial — the AI was tasked with finding contradictions, silent assumptions, and missing documentation. Findings drove several documentation passes before the final PR was merged. The audit process is described in the git history.

Regeneration Workflow

# Regenerate a specific stage netlist
python docs/reverb-tank/stages/gen_stage6_full.py tran

# Validate all netlists
python docs/reverb-tank/validate.py

# Run simulation assertions (requires LTSpice sim outputs)
pytest docs/reverb-tank/test_sync.py -v

# Regenerate component schematics
python docs/reverb-tank/schematics/ghost_spring_schematics.py
# Then copy from /tmp/ghost_sec*.png to docs/reverb-tank/schematics/
